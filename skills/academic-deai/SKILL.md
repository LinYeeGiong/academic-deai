# 学术写作去AI化与去防御性表述（中英双语，通用）

本 skill 处理两类问题：

1. **AI 腔**：模板化开头、空泛强调、机械连接词、三连排比、“不是……而是……”式对比、名词化虚动词、句长过于均匀等生成痕迹。
2. **防御性表述**：没有人质疑时主动自我辩护、层层叠加限定、反驳无人提出的观点、在每句话后面补免责声明，结果论断被稀释、篇幅膨胀。

目标文风是**中性、精确、每个论断都有对应证据**的学术文风。去AI化不是改成口语，也不是给文章“加个性”。

## 硬约束（任何情况下不得违反）

- **不改动**任何数值、单位、百分比、公式、符号、变量名、数据集名、方法名、缩写、引用键（`\cite{}`、`\ref{}`、`\label{}` 等）和 LaTeX 命令结构。
- **不新增事实**：不补实验、不补数据、不补引用，也不把”结果表明”升级成”证明”。改写后如有疑问，用 `scripts/diffcheck.py` 核对改前改后文件的数值和引用键变化。
- **不删除论证内容**：原文有几段，改写后仍有几段，每个论点和每条证据都要保留。
- **不过度矫正**：与证据强度相称的谨慎措辞要保留（见 `references/defensive_hedging.md` 第 3 节”必须保留”）。去防御性表述不等于删光所有限定词。
- **规则库示例不是事实**：改写时不得把规则库里示例的具体描述（”三类制度环境””最相关的差异”等）写进用户的稿子，除非原稿本身已经有这些内容。
- 用户所在项目如果有写作规范、术语表或锁定数字，以项目规则为准，改写前先读。
- 本 skill 用于提升可读性和表达质量，不用于规避期刊、学校或资助机构的 AI 使用披露要求。

## 工作流

### 步骤 0：确认范围

先确定处理对象（文件路径加章节或行号范围，或用户粘贴的段落）、语言和文体（论文正文、摘要、学位论文、基金申请书、审稿回复）。用户没有指定模式时，默认使用 `rewrite`。

| 模式 | 行为 |
|---|---|
| `audit` | 只列问题清单，不改文本 |
| `rewrite`（默认） | 审计后给出改写稿，不动源文件 |
| `apply` | 改写后用 Edit 写回源文件，仅在用户明确要求时使用 |

文体会影响尺度：

| 文体 | 尺度说明 |
|---|---|
| 期刊/会议论文正文 | 标准尺度；愿景语言削减到具体结果 |
| 摘要、贡献列表 | 高影响位置，限定词和自我批评尤其严格 |
| 学位论文 | 标准尺度；第一章引言常有 AI 腔 |
| 基金申请书（`proposal`） | 宽松：愿景表述保留，前提是后面有可行性支撑；先读 `references/proposal_mode.md` |
| 审稿回复（`revision`） | 礼貌让步可保留一次；删掉重复道歉和对审稿意见的过度自辩；不把每条意见都变成论文的局限 |
| 国自然申请书 | 同 `proposal`，另需核对当年官方模板章节要求 |

### 步骤 1：自动扫描

对文件运行扫描脚本，得到带行号的候选问题：

```bash
python <本 skill 目录>/scripts/scan.py <文件> [--lang auto|zh|en] [--lines 120-260] [--format md|text]
```

`<本 skill 目录>` 是当前 `SKILL.md` 所在的目录，随安装位置变化（`~/.claude/skills/academic-deai/`、`~/.agents/skills/academic-deai/`、插件缓存目录等）。不要硬编码某一个路径；不确定时先用 Glob 找到 `scan.py` 再调用。

- 支持 `.tex`、`.md`、`.txt`。处理 `.tex` 时会跳过注释和数学环境，命令名本身不参与匹配。
- 输出每条命中的行号、类别、原文片段和处理建议，末尾附统计：过长句、句长均匀度（变异系数）、句首连接词密度。
- 用户粘贴的文本可以先写入临时文件再扫描。
- 脚本命中只是**候选项**，必须结合上下文逐条判断。例如“显著”后面紧跟统计检验结果时就不算问题，“可能”用于表达真实的不确定性时也不算。

### 步骤 2：人工审计

脚本只能匹配词句，以下结构性问题需要逐段人工检查：

1. **段落模板化**：是不是每段都按”总起句 → 展开 → 总结拔高句”排列？段末是不是总在替读者下结论（”这充分说明了……”）？
2. **论断与证据**：每个经验性论断有没有数字、图表或引用支撑？动词强度有没有超过证据（没做消融却写”验证了模块的作用”，没做统计检验却写”显著”）？先和最强对手比较，而不是只和弱基线比。数值最好报区间而非单一均值。
3. **防御性句子的功能**：用 `defensive_hedging.md` 的六类分类表判断每个候选限定属于哪一类，再决定删除还是保留。
4. **高影响位置**：摘要、贡献列表、段首句、结论是否以局限开头？把限定移到方法或局限性章节，高影响位置以论断或发现开头。
5. **节奏**：是否连续多句长度接近、结构相同？是否连续多句都以连接词开头？
6. **同指异名**：同一对象是否为了”避免重复”被换着叫法（本方法 / 所提框架 / 该模型 / 我们的方案）？学术写作中同一事物应使用同一名称。
7. **审稿回复特有问题**（`revision` 文体）：是否把审稿人可能提出的每个疑问都写成了论文的局限？先区分三类审稿意见——已有数据支持的问题、需要核实的问题、可选追加实验——只在正文中处理影响核心结论的那类。

### 步骤 3：改写

按以下优先级改写：

1. **先改结构，再改词汇**：先删掉没有信息量的总结句、拔高句和重复的限定，再处理具体用词。只替换同义词，读起来仍然是 AI 腔。
2. **直接陈述结果**：“从图 3 可以看出，A 优于 B”改为“图 3 中，A 在各阶段的准确率均高于 B”。
3. **量化或删除**：“显著提升”“大幅降低”这类程度词，要么换成原文已有的数值和比较对象，要么直接删掉。不得编造数值；原文没有数值时，列入“需作者确认”。
4. **限定只说一次，放在该放的位置**：适用范围集中写在实验设置或局限性段落，正文不必每句都重复“在一定程度上”“在本文实验条件下”。
5. **连接词表达真实逻辑**：确实存在因果、转折或递进关系时才用连接词，其余情况靠句子顺序衔接。
6. **让句长有变化**：拆开从句堆叠的长句，也允许出现短句。中文单句一般不超过约 60 字，英文一般不超过约 30 词。

### 步骤 4：输出

按以下结构输出：

```markdown
## 改写结果
<改写后的完整文本；LaTeX 源保持可编译>

## 修改记录
| # | 位置 | 类型 | 原文 | 改为 | 理由 |
|---|---|---|---|---|---|

## 保留未改
- <有意保留的谨慎表述及原因>

## 需作者确认
- <无法从原文判断证据强度、需要补数字或引用才能成立的论断>
```

- 修改记录只列实质修改，纯标点调整可以合并为一行。
- 改写后对新文本**再跑一次扫描脚本**，在报告中给出命中数的前后对比。
- 改写后用 `scripts/diffcheck.py <原文件> <改写文件>` 核对数值和引用键是否完整，把结果贴进「保留未改」一节。
- `apply` 模式写回之前先读取目标文件；如果改的是 LaTeX 稿件，写回后提醒用户重新编译检查。

## 中英文差异速查

| 维度 | 中文 | 英文 |
|---|---|---|
| 典型 AI 痕迹 | 「值得注意的是」「综上所述」「起到了关键作用」「为……提供了新思路」、四字格堆叠、“不是……而是……” | *delve, underscore, pivotal, leverage, seamless*；"It is worth noting that"；em-dash；"not only … but also" |
| 典型防御表述 | 「在一定程度上」「需要指出的是，本文并非……」「尽管存在一定局限性，但……」 | "to some extent"、"While we do not claim …"、"It should be noted that this does not imply …" |
| 虚化动词 | 「进行分析」「实现了提升」「对……加以……」 | "perform an analysis of"、"achieve an improvement in" |
| 主语 | 「本文」不必每句都出现，可以省略主语 | "we" 是标准用法，不必刻意回避 |
| 标点 | 冒号、破折号、分号过多 | em-dash 一律改写为逗号、冒号、括号或拆成两句 |
| 首创/动词强度 | 据我们所知、首次、证明了、验证了 | 说清具体区别；动词强度匹配证据（见 defensive_hedging.md 对照表） |
| 反射式对比 | 不是 X 而是 Y、rather than X, we Y | 直接陈述正面论断；对比只在 X 是文献中真实存在的另一种做法时保留 |
