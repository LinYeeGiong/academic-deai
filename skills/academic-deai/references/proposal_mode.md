# 基金申请书写作规范（国自然 NSFC + NSF/NIH）

本文件补充 `defensive_hedging.md` 的通用规则，专门处理**基金申请书文体**与**期刊论文文体的核心差异**：

> 申请书出售的是**愿景加可行性**，不是已完成的结果。
> 评阅人从第一页打分，后面只是确认。

这意味着期刊论文中需要削减的"愿景语言"（长远目标、开创性、奠定基础）在申请书中**是恰当的、被期待的**——前提是后面有可信的可行性支撑。

**核心校准原则**：
- 期刊论文：**论断 ≤ 证据**（声明不能超过数据）
- 基金申请书：**愿景 + 可行性相匹配**（雄心壮志可以保留，但每一条都需要根基）

---

## 1. 国家自然科学基金（NSFC）面上项目

### 1.1 正文章节结构

NSFC 面上项目正文通常包含以下章节（以官方模板为准，以下结构供参考）：

| 章节 | 核心任务 | 常见防御性弱点 |
|---|---|---|
| **立项依据** | 说清研究意义、国内外现状、存在的问题和本项目的切入点 | 只罗列文献，不说清"空白在哪里""为什么本团队能填上" |
| **研究内容** | 具体研究什么，不是方法是目标/问题 | 把"研究内容"写成研究方法（研究内容 = 问什么；研究方法 = 怎么做） |
| **研究目标** | 本项目结束时能交付什么具体结果 | 目标太笼统——"探索""了解"不是可核查的目标 |
| **拟解决的关键科学问题** | 2–3 个机制层面的核心问题，不是技术问题 | 把工程挑战当科学问题；超过 3 个说明没想清楚 |
| **研究方案** | 每个研究内容对应的方法、技术路线 | 方案太笼统，没有说明在什么条件下判定成功 |
| **可行性分析** | 用已有工作、团队能力、合作资源证明计划可以执行 | 只写"本课题组有多年经验"，没有具体成果或数据 |
| **特色与创新** | 方法、思路或视角上的具体新颖之处 | 写成优点列表（系统全面、多维度），不是可检验的区分点 |
| **年度计划** | 可以核查的里程碑，时间合理 | Aim 2/3 依赖 Aim 1 全部完成（多米诺结构），风险评阅 |

> **注意**：2026 年 NSFC 申请书模板以基金委官方发布版本为准。本文件提供的结构是基于惯例的参考框架，用前请核对当年正式模板。

### 1.2 NSFC 典型防御性弱点

**弱点 1：立项依据只写文献综述，没有"空白"**

> 改前：*国内外学者已对 X 开展了大量研究，取得了丰硕成果。本文在此基础上开展进一步研究。*
>
> 改后：*现有方法假设 A，无法处理 B 场景。本项目研究当 A 不成立时的 C 机制，填补这一空白。*

**弱点 2：研究内容写成了方法步骤**

> 改前：研究内容一：利用深度学习构建预测模型。
>
> 改后：研究内容一：揭示 X 特征与 Y 结果之间的量化关系（是什么问题，不是做什么操作）。

**弱点 3：可行性分析只写"经验丰富"**

> 改前：*本课题组长期从事相关研究，具有扎实的研究基础和丰富的研究经验。*
>
> 改后：*项目负责人已在 X 场景下验证了核心方法（发表于 JournalA，数据见图 1），本项目是对该成果在 Y 维度的延伸。*

**弱点 4：特色与创新写成优点列表**

> 改前：*本文具有以下创新点：（1）研究视角新颖；（2）方法系统全面；（3）数据丰富可靠。*
>
> 改后：*本项目的创新在于：以往方法 A 假设 P，本文首次在不要求 P 的条件下建立理论框架，并提供了可证伪的预测（见研究内容三）。*

### 1.3 NSFC 中应当保留的表达

在可行性支撑充分的条件下，以下表达在 NSFC 申请书中是**合适且预期的**，不要削减：

- 长远目标（"从根本上解决 X 问题"）——前提是本项目是迈向该目标的有明确边界的一步
- "本项目是 A 的首次系统研究"——前提是确实能检索到空白
- "具有重要科学意义和应用价值"——前提是后面有具体说明
- 年度计划中的里程碑表述（"完成……建立……"）

## 2. NSF / NIH 申请书（供参考）

### 2.1 NSF 面上项目（Grant Proposal）

核心结构：**Project Summary**（1 页：Overview + Intellectual Merit + Broader Impacts）→ **Project Description** → **References**。

评阅人从 Project Summary 打第一印象分，然后在 Project Description 前 1–2 页找到长远愿景、本期目标、问题 gap、具体研究方向和预期成果。

**评阅标准**：
1. **Intellectual Merit**：是否能推进知识边界
2. **Broader Impacts**：是否对社会有具体可测量的影响

**Project Description 前几页必须覆盖的内容**：

| 要素 | 说明 |
|---|---|
| Hook | 为什么这个问题重要，用具体的场景/代价，不用"非常重要" |
| Gap | 现有方法缺什么，这个缺口的具体后果 |
| Central idea | 本项目的核心思路，一句话 |
| Thrusts/Aims | 简洁并列，每个独立成立 |
| Payoff | 成功后能改变什么，要具体 |

**NSF 典型弱点**：

- **模糊的重要性**（"这是一个重要且及时的问题"）→ 说清楚不解决这个问题的具体代价
- **以方法为目标的 Aim**（"Aim 2: 将迁移学习应用到数据集"）→ 改成结果/问题导向（"Aim 2: 确定迁移学习是否改善了 X 人群的早期检测，以及对哪些亚组有帮助"）
- **多米诺结构**（Aim 3 依赖 Aim 2 完全成功）→ 改成并列独立，各自有价值的结果
- **Broader Impacts 模板化**（"将培训学生并通过报告和论文传播"）→ 具体的计划、命名的项目或课程、可量化的外延

### 2.2 NIH R01

**Specific Aims 页是整个申请中最关键的一页**，评阅人花最多时间阅读。

标准行文结构：

1. **问题与 gap**：问题是什么，已知什么，什么是关键缺口
2. **长远目标**和**中心假说**（含形成依据）
3. **"本申请的目标是……"**，加假说的形成依据
4. **2–3 个 Aims**：每个一行目标 + 一句方法 + 预期结果
5. **Payoff**：成功后的影响

**保留这些，它们是强度信号**：
- 大胆的长远目标（加本期工作是该目标的有边界的一步）
- 中心假说的明确陈述（假设是可证伪的承诺，不是"探索是否可能"）
- Aims 之间的独立性声明
- 可行性证据（初步数据图表、合作机构的信件）

## 3. 申请书与论文的通用校准规则

| 维度 | 期刊论文 | 基金申请书 |
|---|---|---|
| 愿景语言 | 削减到具体结果 | 保留，前提是后面有可行性支撑 |
| 限定词 | 与已有数据相称 | 与计划的研究设计相称（合理假设 ≠ 防御） |
| 不利结果 | 如实陈述并分析 | 已完成的预实验不利结果：如实说明并给出应对方案 |
| 首创声明 | 谨慎，容易被追问 | 可以用，前提是真正的空白，并说清楚 |
| "进一步研究" | 一般是套话，删除 | 合理的"本期工作之外"界定，保留 |

**示例规则不是事实**：本文件中的改写示例提供的是结构和措辞模板，不能直接用进申请书中——申请书里的每一条数据、成果、合作者、初步结果都必须来自申请人自己的真实记录，不能虚构。
